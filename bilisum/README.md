# bilisum —— 在 DSH 里贴一个 B 站链接，出一份速读稿（视频信息 + 30 秒速读 + 重点提炼）

不用装插件。`yt-dlp` 取内容、`ffmpeg` 转码、本机 `SenseVoice` 识别，最后**由我（对话里的模型）读文本做总结**。

## 日常怎么用（只记这两条就够）

**一、把链接贴给我就行**——完全不用自己敲命令：

```
https://www.bilibili.com/video/BV1iz4R6EEFk
```

或者直接 `BV1iz4R6EEFk`；**手机分享出来的 `https://b23.tv/xxxx` 短链也直接贴**，
不用先展开——工具自己解析（2026-10-15 修好了短链丢基本信息的 bug，见「常见问题」）。
我会自动选字幕/本地识别，只给你一份**速读稿**（默认产出见下节）。

**二、想自己跑**：

```powershell
cd C:\Users\23077\Desktop\work_place\b速读\bilisum
node bilisum.mjs get "BV号或链接"      # 转写落 cache\，摘要打在终端
```

| 命令 | 用途 | 需要 cookie | 耗时 |
|---|---|---|---|
| `get` | **日常用这个**：字幕优先，失败落本地识别 | 有则用 | 秒级 / 3–6 分钟 |
| `subs` | 只要官方字幕 | 是 | 秒级 |
| `asr` | 只要本地识别 | 否 | 3–6 分钟 |
| `probe` | 只看标题/时长/有无字幕（**不抓评论**） | 否 | 秒级 |
| `comments` | 只看热门评论 | 是（否则只有前 3 条） | 秒级 |

默认只在终端打摘要；要全量数据加 `--json`。

评论相关开关：`--comments N`（别名 `--top N`，默认 40 条）、`--no-comments`（不抓）。

## 默认产出（2026-10-13 起用户指定；2026-10-14 补"必须带视频信息"；2026-10-15 补"我的看法 + 热门评论分析"）

**唯一的交付物是《速读稿》，固定五块：**

1. **视频基本信息** —— 作者名 + 粉丝数、发布时间、播放量、评论数、点赞/投币/收藏/弹幕/分享、时长、链接（用户靠这些判断这条视频可不可信，**必须有**）
2. **30 秒速读** —— 三五句话说清这条视频讲了什么、结论是什么
3. **重点提炼** —— 分论点展开，带时间点（纯数字 `00:01:43`，不写可点击链接）
4. **我的看法** —— 2026-10-15 用户要求：要有立场、点名具体段落，不写"整体不错、值得一看"
5. **热门评论分析（约 10 条）** —— 2026-10-15 用户要求：置顶/最高赞/观点分歧/补充实用信息的优先，纯表情水评舍掉

**交付方式（2026-10-14 用户要求）：速读稿以文字形式直接写在回复对话正文里**，不发文件、不用文件卡片代替正文。`out/<BV>-速读稿.md` 照常落盘留档，但用户看的是对话正文。

**其余一律默认不产出**（用户明确说不看）：中文全文稿、原始转写、关键数字一览、名词校正表、方法说明、口径声明，以及"要不要我再做 XX"之类的收尾推销。

### 热门评论从哪来（2026-10-15 新增）

转写文件头里会自动多一块 `## 热门评论`（默认 40 条，含置顶标记、赞数、回复数、IP 属地、时间、楼中楼前 3 条），
模型写速读稿的第 4、5 块时就地取材——**不写进文件头它不一定看得到**。

| 项 | 接口 | 说明 |
|---|---|---|
| 评论列表 | `/x/v2/reply?type=1&oid=<aid>&sort=2&nohot=0&ps=20&pn=N` | `sort=2` 即"热门"排序 |
| 评论总数 | 同上的 `page.count` | 与 `view.stat.reply` 同源，可互校 |
| 置顶评论 | 同上的 `top_replies[]` / `upper.top` | 标 `置顶` / `UP主` |
| 楼中楼 | `/x/v2/reply/reply?root=<rpid>&ps=10` | 取赞数最高的前 3 条 |

实测踩过的坑（改代码前先看 `fetchComments` 的注释）：

- **必须带 `sort`**。不带时接口返回 `code=0` 但 `replies` 为空、`page.count=0`——静默骗人，不报错。
- **匿名只给前 3 条**，且 `pn≥2` 直接空返回。带登录 cookie（`cache/cookies.txt`）才能一页 20 条、正常翻页。
  没 cookie 时工具**降级**为"只取前 3 条"，并在转写文件头和速读稿里如实标注。
- `pn` 的返回顺序**不是纯按赞数**（实测第 1 页里混着 7 赞的、400 赞的排在其后），
  所以工具自己再排一次：**置顶最前，其余按赞数降序**。
- 子评论赞数门槛不设（小视频"热评"常只有个位数赞），只对最终展示的前 8 个楼层拉楼中楼，避免把小接口打爆。

### 视频基本信息从哪来

| 字段 | 来源 |
|---|---|
| 作者名、作者 mid | `api.bilibili.com/x/web-interface/view` → `owner` |
| **粉丝数** | `api.bilibili.com/x/relation/stat?vmid=<mid>` → `follower` |
| 发布时间 | `view` → `pubdate`（UNIX 秒，按北京时间显示，并折算"多少天前"） |
| 播放/评论/弹幕/点赞/投币/收藏/分享 | `view` → `stat` |
| 简介、官方提示（如"个人观点，仅供参考"） | `view` → `desc` / `argue_info.argue_msg` |

- 两个接口都是**公开接口，不需要 cookie**，所以没有登录态也能带全这些信息。
- 取不到时**只降级、不报错**：终端和转写文件里会明确写"数据未取到"，模型写速读稿时必须照实说明，不许编。
- 同一进程内按 BV 号缓存，`probe`/`subs`/`asr`/`get` 之间不重复请求。

对应到工具行为：

| 东西 | 默认去哪 | 怎么改 |
|---|---|---|
| 转写全文 | `cache/<BV>.transcript.md`（**中间产物**，喂给模型读的，不是交付物；**头部带"视频基本信息"块**） | 加 `--full` 才写正式转写到 `out/<BV>.md` |
| 时间轴写法 | 中间产物：`[00:00:01] 正文`（**不带链接**，省 token） | `--full` 的正式转写：`<a href="…?t=1">[00:00:01]</a> 正文`（可点击） |
| 终端输出 | 视频基本信息 + 来源 / 段数 / 字数 / 覆盖时长 / 文件路径 | 加 `--preview` 打开头三段，加 `--json` 出全量（含 `meta`） |
| `out/` | 只放《速读稿》`<BV>-速读稿.md` | — |

> 基本信息块写进 `cache/<BV>.transcript.md` 的**文件头**是有意为之：模型写速读稿时读的就是这个文件，
> 写在里面它才一定看得到，不指望它自己想起来去查。

> 转写仍然必须"存在"（不然没素材可总结），只是**不再当成产物摆出来**：它待在 `cache/`，
> 和 `audio.m4a`、裸 PCM 一样属于可随时删的中间文件。

**Cookie 失效了怎么办**（症状：字幕突然拿不到）：

```powershell
node scripts/set-cookie.mjs --check     # ✓ 登录有效 / ✗ 未登录
```

失效了就重新复制一次 cookie 跑 `set-cookie.mjs`（步骤见下文）。

> 模型 230 MB、`sherpa-onnx`、`yt-dlp`、`ffmpeg` 都已就位，**不需要重复安装**。
> cookie 存在 `cache/cookies.txt`，重启也在。不想给 cookie 也能用——走本地识别即可。

## 怎么给我 B 站 Cookie

字幕路线需要登录态。**匿名状态实测字幕命中 0/40**，所以必须登录。

### 方法 A：复制为 cURL（推荐，不用去找 cookie 那一行）

1. 用 Edge 或 Chrome 打开 <https://www.bilibili.com>，**确认已登录**（右上角有头像）
2. 按 `F12` 打开开发者工具，切到 **Network / 网络** 标签
3. **按 `F5` 刷新页面**（不刷新的话请求列表是空的）
4. 在请求列表里**右键任意一条**发往 `bilibili.com` 的请求
5. 选 **Copy → Copy as cURL (bash)**
   （Edge 中文：复制 → 以 cURL 格式复制）
6. **把整段粘给我** —— 里面已经包含了 cookie

不需要你手动挑字段，我那边会解析。

### 方法 B：只要 SESSDATA

1. `F12` → **Application / 应用程序** 标签（看不到就点标签栏的 `>>`）
2. 左侧 **Storage → Cookies → https://www.bilibili.com**
3. 找名字为 **`SESSDATA`** 的那一行，点它
4. 下方 **Value** 列双击全选复制
5. 给我 `SESSDATA=<值>`

> 注意：值里的 `%2C` 是 URL 编码的逗号，**原样复制，别解码**。

### 我拿到之后做什么

```powershell
node scripts/set-cookie.mjs "<你粘贴的内容>"
```

它会：解析 → 调 B 站 `nav` 接口**验证真的登录了** → 才写入 `cache/cookies.txt`（Netscape 格式）。

验证这步很关键：不验证的话，cookie 过期时的症状是"字幕莫名其妙取不到"，你会分不清是**没登录**还是**这个视频本来就没字幕**。校验失败会明确报 `code=-101 账号未登录`，且**不会落盘**。

随时可复查：

```powershell
node scripts/set-cookie.mjs --check
```

### 安全提醒

- `SESSDATA` **等价于你的 B 站登录态**，拿到它等于拿到账号
- 它只存在 `bilisum/cache/cookies.txt`，已被 `.gitignore` 排除，不会进版本库
- 想让它失效：B 站 → 设置 → 安全隐私 → **退出所有设备**
- **不想给完全可以**：`asr` 本地识别路线不需要 cookie（慢一点，但免费、覆盖全部视频）

> 为什么不能我直接读浏览器：Edge/Chrome 的 cookie 库被运行中的浏览器**独占锁定**，
> 连 `CreateFileW` 全共享模式和 `robocopy /B` 都拿不到（本会话未提权）。
> 唯一免关浏览器的办法是 Firefox（其 `cookies.sqlite` 不加密也不独占），但本机没装。


## 为什么这么设计（每条都是实测结论）

| 决定 | 原因 |
|---|---|
| B 站**必须直连** | 系统代理 `127.0.0.1:7890` 会让 `api.bilibili.com` 返回 **HTTP 412**；而 HuggingFace / GitHub release **必须走代理**（直连超时）。两个目标策略相反 |
| 清代理要连 `NO_PROXY` 一起设 | Python 的 `getproxies()` 会读 Windows 注册表，只清 `HTTP_PROXY` 不够 |
| `TEMP`/`TMP`/`TMPDIR` 必须重定向 | `yt-dlp.exe` 是 PyInstaller 单文件包，默认 TEMP 下会 `Could not create temporary directory!` |
| BV 号**只规整前缀** | body 是大小写敏感 base58：`bv1gj411x7h7` 会解析成**另一个真实视频**（静默指错），`BV1GJ411X7H7` 直接报错 |
| 走**裸 PCM** 不走 WAV | ffmpeg 的 WAV 头不规范（插 `LIST`/`INFO`/`fact`，`data` 在 offset **78** 而非 44） |
| 长音频**必须分窗** | SenseVoice 整段吃会**静默返回空文本、退出码仍是 0**；69 分钟音频峰值内存 **58 GB** |
| 窗长 30 s、切点 ±1.5 s 吸到能量最低处 | 同源项目实测：15–30 s 已到顶（约 6.4 字/秒）；±1.5 s 吸附比固定切点多留 **3.8%** 内容 |
| 用 Node 不用 PowerShell | 脚本含中文时，PowerShell 无 BOM 会按 GBK 读，字符串字面量会被吃坏导致语法错误 |

## 字幕 vs 本地识别

| | 字幕（`subs`） | 本地识别（`asr`） |
|---|---|---|
| 需要 | **登录 cookie（`SESSDATA`）** | 无（模型已就位） |
| 耗时 | 秒级 | 16 分钟视频约 3–6 分钟 |
| 准确度 | 平台官方字幕，最准 | SenseVoice，中文口播很好 |
| 覆盖 | 有字幕的视频 | 全部 |
| 成本 | 0 | 0 |
| 匿名可用性 | **实测 0/40 命中**（必须登录） | ✅ 完全可用 |

`get` 会自动选：先试字幕，拿不到就落本地识别。

> **所以：没有 cookie 也能用**，只是走 ASR（慢一点，但免费且覆盖全部）。
> Cookie 只影响能否走"字幕"这条快车道。

### 关于"B 站不稳定"的更正

早先我记录过"匿名请求间歇性失败（成功/失败/成功）"。**复测 18 次全部成功**——
那次失败是**我自己突发限流**造成的：短时间内连打排行榜 API、搜索、多次探测。
正常使用（一个视频一次探测）是稳定的。代码里保留重试只是为了顶住偶发限流。

## 字幕是怎么拿到的（这段很反直觉）

**没有走 yt-dlp。** 实测 yt-dlp 对某个视频报"无字幕"，而 B 站的 `player/v2` 接口
明明返回了 `lan=ai-zh`。而且 yt-dlp 拿到的字幕**没有可用的时间轴**，我们要的正是时间轴。
所以直接走官方接口：

```
view?bvid=BV…            → aid, cid, 标题, 时长
player/v2?aid=&cid=      → subtitle.subtitles[] → subtitle_url（带签名的 .json）
下载那个 url             → { body: [{from, to, content}, …] }  ← 官方精确时间轴
```

### 坑：同一个视频有一堆"字幕文件"，只有一个是完整的

同一个视频连调 4 次 `player/v2`，返回的 `subtitle_url` **指向不同文件**，
内容长度天差地别，而 **HTTP 状态码每次都是 200**：

| 返回的文件名（hash 前缀） | 段数 | 覆盖时长 |
|---|---|---|
| `117166825281470413348692…` | **1119** | **2710s ✓ 完整** |
| `113368631412447264608165…` | 30 | 93s |
| `117166825281470413348692…` | 1119 | 2710s ✓ 完整 |
| `16560705161614942327d728…` | 138 | 306s |

那些残缺文件里甚至出现过**完全不相干视频的字幕**（短剧台词），不是截断，是错文件。

**规律**：完整那份的文件名以 **`${aid}${cid}`** 开头
（上例 `117166825281470` = aid，`41334869261` = cid）。

**做法**：每轮重新请求 `player/v2`，先按文件名筛出规范文件，再下载并用
**视频已知时长**校验覆盖度（不足九成视为不完整）。筛名这步很关键——加之前
6 次重试全是垃圾，加之后 **6/6 完整、每次只投 2 次请求**。

> 顺带更正一个我先前写错的判断：curl 与 node fetch 对**同一个 URL** 拿到的长度
> 各自完全稳定（38368 / 33476），所以"截断"不是网络或客户端问题，纯粹是选错了文件。

## 常见问题

**`错误：B 站风控拦截（HTTP 412）`** → 代理没关掉。确认走了 `--proxy=` 且 `NO_PROXY=*`。

**`yt-dlp 探测失败`** → 先跑 `node bilisum.mjs probe <url>` 看是不是链接本身的问题。

**字幕为空** → 要么没登录（cookie 缺失/过期），要么该视频确实没字幕。B 站部分视频需要在播放器里手动开启「中文 AI」字幕才会生成。

**识别结果为空** → 检查窗长。如果某个窗特别长（> 60 s）说明切点吸附异常。

**`b23.tv` 短链（手机分享的链接）没有视频基本信息、字幕也拿不到** → 已修（2026-10-15）。
根因：yt-dlp 给 B 站的 `info.id` 是 `BV<10 位>_p<页码>`，**单 P 视频也带 `_p1`**；
这个串不是合法 bvid，`/x/web-interface/view` 直接 `code=-400`，于是基本信息和
官方字幕的兜底请求**一起**失效（只能退回慢得多的本地识别）。
现在 `bareBvid()` 会先剥掉 `_pN` 再调接口，多 P 视频按 `pages[]` 取对应 `cid`。
**自检**：`node bilisum.mjs probe "https://b23.tv/xxxx"` 应该打印出「作者（粉丝 …）」那一整块。
